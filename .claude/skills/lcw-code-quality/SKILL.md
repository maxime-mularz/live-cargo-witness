# Code quality — Live Cargo Witness

A change is done when every step below is true. Do them in order; do not skip a step because the
change "looks small". The hackathon judges read this code, and the verifier is the product's
credibility: a silent regression there costs more than any feature.

## 1. Before writing code

- Read `CLAUDE.md` (hard rules 1–9) and the module's docstring. If the change touches a name that
  appears in several files (a tool, a status, an evidence type, a rule field, a dossier field),
  load the `lcw-consistency` skill now, not at the end.
- Behaviour change or bug fix → **write the failing test first** in `new/tests/`, run it, see it
  fail for the right reason. A fix without a test that failed before it is not a fix.
- Never touch, open or decrypt `new/bench/reserved*` before the code freeze (Nov 3, 18h Paris).
  Never tune prompts or code against it. Prompt tuning happens on `bench/dev` only.

## 2. While writing code

- Python 3.12, standard library first. New dependency → justify it, add it to `requirements.txt`.
- No hard-coded threshold, limit or value that will appear in a case file: it comes from a rule
  card, a dossier field or a piece of evidence (rule 4). Constants of the method itself (sampling
  defaults, window sizes, caps) are named module constants with a comment saying why.
- Model output is untrusted input. Anything coming from `chat`, `read_document_image`,
  `segment_crate_image` or `transcribe` can be missing, mistyped, wrapped in prose or wrong. Parse
  defensively, report the problem back to the model as a tool error, never crash the run.
- Errors that may contain provider responses go through `lcw.env.redact()` before reaching the
  model, the journal, a results file or the terminal. Never print a key, never log a request header.
- Free model text (reasons, final messages) is never shown as fact: mask it with
  `lcw.vocab.mask_forbidden` and label it "unverified model text".
- Offline stand-ins are labelled as such wherever they are displayed. A scripted client never
  produces a published score.
- Keep functions short and named for what they decide. Comments say *why*, not *what*.

## 3. Checks (run them, read the output)

```bash
ruff check new                      # config in pyproject.toml; fix the code, never add a noqa to pass
python3 -m pytest new/tests -q      # full offline suite, must be green
python3 new/scripts/run_bench.py new/bench/dev --dry-run   # if agent, tools, runner or casefile changed
```

If the dry run no longer gives 20/20 phase-1 and 14/14 investigations with every case written,
the plumbing broke — find out why before going further.

## 4. Independent review for the sensitive modules

`lcw/verifier.py`, `lcw/agent.py`, `lcw/tools.py`, `lcw/casefile.py`, `lcw/runner.py` and
`lcw/predeparture.py` decide what enters a signed record. Any non-trivial change to them gets a
review by a separate agent that did not write the change:

- give it the files and the diff, the hard rules, and what the change is meant to do — not your
  conclusion that it works;
- ask for real bugs only (wrong record written, verifier bypass, crash on plausible model output,
  secret leak, test that does not test what it claims), each with a failing scenario;
- turn every confirmed finding into a regression test, then fix it.
- review the fixes too: a second pass on the agent loop found ten bugs in the first round's
  fixes (a wide claim standing for several deviations, a record written without any reading);
- check that each new test fails without its fix (revert the line, run the test, restore).

## 5. Hard-rules checklist (answer each before committing)

- [ ] No client data, no real company or person name (check `.private-names` via `lcw-release-check`).
- [ ] No secret in code, tests, docs or chat; keys only in `.env`.
- [ ] The verifier is not weakened: no check removed, no tolerance widened, no status allowed
      without its evidence. If a legitimate claim is rejected, fix the claim or the prompt.
- [ ] No veterinary vocabulary in what the agent writes; `lcw/vocab.py` only grows.
- [ ] Nothing is sent: tools draft, humans sign and send.
- [ ] IATA wording: "built for live-animal shipments subject to the IATA LAR" — never
      "specialist", "certified", "approved", no logo, no LAR text.
- [ ] Synthetic data carries `synthetic: true` and a SYNTHETIC banner where shown.
- [ ] `expected.json` files are regenerated by `generate_bench.py`, never hand-edited.
- [ ] Docs that describe the change are updated (`lcw-consistency`).

## 6. Commit

- Run `python3 new/scripts/check_release.py` (the `lcw-release-check` skill) before pushing.
- One commit per coherent change, message in English, imperative, saying what and why.
- Never force-push or rewrite history without Maxime's explicit approval.
